# RCA — Deploy build failure (run 82449d19-e24c-4408-9b1f-751002287140)

## Summary
The redeploy of **consultation-astro** failed at the `build_image` step, in Cloud Build step #8 `frontend-build-push` (the Cloudflare/R2 frontend build). Root cause is a **source-level problem in `frontend/package.json`**, not a manifest or infrastructure issue.

## Root cause
`frontend/package.json` (line 110) contains:

```json
"packageManager": "npm@11.9.0"
```

The Emergent farm/Cloudflare frontend build installs dependencies with **Yarn** (`yarn install` in both `Dockerfile.cloudbuild` frontend stage and `build-frontend-artifacts.sh`). When Yarn/Corepack sees a `packageManager` field — especially one pinning a different manager (`npm`) — it refuses to run and aborts:

```
error This project's package.json defines "packageManager": "yarn@npm@11.9.0".
However the current global version of Yarn is 1.22.22.
Presence of the "packageManager" field indicates that the project is meant to be used with Corepack...
Corepack must currently be enabled by running corepack enable in your terminal.
```

(The "yarn@" prefix in the log is Yarn 1.x echoing its own name in front of the declared value `npm@11.9.0`.)

Earlier runs (e.g. 88461261 on 2026-10-03, 3fcd8d7c on 2026-09-29) built successfully, so this `packageManager` field was introduced into the frontend source after the last good deploy.

## Reproduction (eph sandbox, source at /app/scratch)
1. `cd frontend && yarn install` → **failed, exit 1**, with the exact Corepack `packageManager` error above (failure reproduced).
2. Removed line 110 (`"packageManager": "npm@11.9.0"`) → re-ran `yarn install` → Yarn passed the Corepack gate and began resolving dependencies (the sandbox was later OOM-killed on the large install; that is a sandbox memory limit, not the build error — production build has adequate resources).

## Fix (E1 to apply in the source environment)
In **`frontend/package.json`**, delete the `packageManager` line:

```diff
     "typescript": "^5.0.0"
-  },
-  "packageManager": "npm@11.9.0"
+  }
 }
```

i.e. remove `"packageManager": "npm@11.9.0"` (and the trailing comma on the preceding `}` so the JSON stays valid). Do not replace it with a yarn pin — simply removing it lets the build's Yarn 1.22.22 run normally, matching the previously-successful deploys.

After the fix is committed to source, re-trigger the deploy.

## Classification
- Failed step: `build_image` → Cloud Build step #8 `frontend-build-push`
- Owner: **Code** (source file `frontend/package.json`) — applied by E1, not via deployment manifests.
- No manifest change made. No redeploy fired (redeploying unchanged source would fail identically).
